Adding Pages

How to create a new page in the framework-free HTML build and wire it into the Vite bundle and the sidebar navigation.

Overview

This template is a Vite multi-page app (MPA). There is no router and no framework — each page is a standalone .html file at the project root that boots the shared web components (<apex-sidebar>, <apex-header>, and friends) via the entry script /src/main.js. Adding a page takes three steps:

  • Create my-page.html at the project root, copied from an existing page's shell.
  • Register it as a build input in vite.config.js.
  • Add a nav link object in src/components/apex-sidebar.js.

Step 1: Create the Page File

Copy an existing page such as orders.html to a new file at the root. Every page needs three things: the no-flash theme script in the <head>, the layout shell (<apex-sidebar> + <apex-header> + <main>), and the /src/main.js module at the end of the body:

The page will be served at /reports.html. Setting active="reports.html" on the sidebar highlights the matching nav link; if you omit it the sidebar falls back to the current filename.

Auth and error pages live in subfolders (e.g. auth/login.html). Those omit the dashboard shell and use lighter markup — copy one of those instead when you need a standalone page.

Step 2: Register the Build Input

Vite only bundles HTML files listed under build.rollupOptions.input. Open vite.config.js and add one entry — a unique key mapped to the resolved file path:

// vite.config.js
export default defineConfig({
  plugins: [tailwindcss()],
  build: {
    rollupOptions: {
      input: {
        main: resolve(import.meta.dirname, "index.html"),
        orders: resolve(import.meta.dirname, "orders.html"),

        // Add your new page:
        reports: resolve(import.meta.dirname, "reports.html"),
      },
    },
  },
});

During development (npm run dev) Vite serves any root HTML file directly, so the page is reachable immediately. The input entry is what tells the production build (npm run build) to emit reports.html into dist/. Forget this step and the page works in dev but disappears from the build.

Step 3: Add to the Sidebar Navigation

The sidebar is a web component, src/components/apex-sidebar.js, that renders its links from plain config arrays at the top of the file. Add an item object to the relevant group in navGroups (or to systemNav):

// src/components/apex-sidebar.js
const navGroups = [
  // ...existing groups
  {
    label: "Commerce",
    items: [
      { icon: "shopping-cart", label: "Orders", href: "orders.html", badge: "12" },
      { icon: "package", label: "Products", href: "products.html" },

      // Add your new link:
      { icon: "file-text", label: "Reports", href: "reports.html" },
    ],
  },
];

Each item is an object with icon, label, and href. The optional badge renders a small count pill (and a dot when the sidebar is collapsed). The component marks a link active by comparing the page's active attribute (or current filename) against the link's href, so no extra wiring is needed.

The icon value must be one of the curated Lucide names registered in src/lib/icons.js (e.g. file-text, package, users). To use an icon that isn't there yet, add its import and map entry in that file — only registered icons are bundled, which keeps the build lean.

Using the Reusable Components & Classes

Build your page content from the same primitives the rest of the template uses, so it inherits the theme tokens automatically. The reusable styles are defined in src/styles/main.css — use these classes instead of repeating long utility strings:

<div class="grid gap-4 sm:grid-cols-2 lg:grid-cols-3">
  <div class="apex-card p-5">
    <h3 class="text-sm font-medium text-muted-foreground">Monthly Revenue</h3>
    <p class="mt-2 text-2xl font-bold tracking-tight">$48,250</p>
  </div>
</div>

<div class="mt-6 flex items-center gap-3">
  <button class="apex-btn apex-btn-primary">
    <i data-lucide="download" class="h-4 w-4"></i> Export
  </button>
  <button class="apex-btn apex-btn-outline">Cancel</button>
</div>

Common building blocks include .apex-card, the button family (.apex-btn plus .apex-btn-primary / -outline / -secondary / -ghost / -destructive), and the form controls .apex-input, .apex-select, .apex-textarea, .apex-label, and .apex-switch.

Adding Icons

Icons are rendered with vanilla Lucide. Place an <i data-lucide="..."> placeholder anywhere in your markup; the entry script calls renderIcons() after the DOM is ready and swaps each placeholder for its SVG. To make a new icon available, add it to the import and map in src/lib/icons.js:

// src/lib/icons.js
import {
  createIcons,
  /* ...existing imports */
  FileBarChart,   // 1. import the icon (PascalCase)
} from "lucide";

const icons = {
  /* ...existing entries */
  FileBarChart,   // 2. register it in the map
};

// Now usable in markup as: <i data-lucide="file-bar-chart"></i>
