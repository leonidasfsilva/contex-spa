Theming

Learn how the color system works and how to customize the look and feel of Apex Dashboard — the framework-free HTML build.

Two ways to change colors. For a quick preview, open the theme customizer (the palette icon in the header) to switch accent color, theme, border radius, and direction live — your choice is saved to localStorage and re-applied on every page. To set your brand color permanently, edit the --primary token in src/styles/main.css (shown below).

OKLCh Color Tokens

All colors are defined as CSS custom properties using the OKLCh color space. OKLCh provides perceptually uniform lightness, which makes it easier to build consistent palettes and keep light and dark variants in balance. Every token lives in a single stylesheet: src/styles/main.css.

There are two source-of-truth blocks — :root holds the light-mode values and .dark overrides them for dark mode:

:root {
  --radius: 0.625rem;
  --background: oklch(0.985 0.002 230);
  --foreground: oklch(0.155 0.015 230);
  --card: oklch(1 0 0);
  --primary: oklch(0.55 0.175 160);
  --primary-foreground: oklch(0.985 0.002 230);
  --muted: oklch(0.96 0.005 230);
  --border: oklch(0.922 0.005 230);
  --ring: oklch(0.55 0.175 160);
  /* ...more tokens */
}

.dark {
  --background: oklch(0.075 0 0);
  --foreground: oklch(0.922 0.005 230);
  --card: oklch(0.19 0 0);
  --primary: oklch(0.65 0.19 160);
  --border: oklch(0.28 0 0);
  --ring: oklch(0.65 0.19 160);
  /* ...more tokens */
}

The OKLCh format is oklch(lightness chroma hue) where lightness is 0–1, chroma is 0–0.4, and hue is 0–360 degrees. Tailwind CSS v4 maps these raw tokens to utility classes through the @theme inline block at the top of main.css, so --primary becomes bg-primary, text-primary, ring-primary, and so on:

@theme inline {
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-card: var(--card);
  --color-muted: var(--muted);
  --color-border: var(--border);
  --color-ring: var(--ring);
  /* ...one --color-* mapping per token */
}

Changing the Primary Color

To rebrand the dashboard, update the --primary token in both the :root (light) and .dark blocks. Keep the matching --ring and --sidebar-primary in sync so focus rings and the active sidebar accent match. To switch the default teal (hue 160) to blue (hue 250), change only the hue value:

/* Light mode */
:root {
  --primary: oklch(0.55 0.175 250);          /* hue 160 -> 250 (blue) */
  --primary-foreground: oklch(0.985 0.002 230);
  --ring: oklch(0.55 0.175 250);
  --sidebar-primary: oklch(0.60 0.175 250);
}

/* Dark mode */
.dark {
  --primary: oklch(0.65 0.19 250);
  --primary-foreground: oklch(0.075 0 0);
  --ring: oklch(0.65 0.19 250);
  --sidebar-primary: oklch(0.65 0.19 250);
}

The change propagates everywhere bg-primary, text-primary, or ring-primary is used — buttons (.apex-btn-primary), links, active states, badges, and sidebar accents all update at once. No build-time config is involved; Tailwind v4 resolves the variables at runtime.

Tip: keep --primary and --chart-1 on the same hue. The default theme sets both to hue 160 so the first chart series matches the brand color.

Semantic Color Tokens

The design system uses semantic names rather than raw colors. Most tokens have a *-foreground counterpart for text that sits on top of them:

Token Purpose
--primaryBrand color, primary buttons, active states
--secondarySecondary actions, subtle backgrounds
--cardCard and panel surfaces (.apex-card)
--mutedMuted backgrounds, code blocks, inline code
--accentHover states, highlights
--borderDefault border color (applied to * in the base layer)
--ringFocus-visible rings on inputs and buttons
--destructiveError states, delete actions
--successSuccess indicators, positive trends
--warningWarning badges, caution states
--chart-1 … --chart-5Chart color palette (5 series colors)
--sidebar-*Sidebar surface, foreground, accent, border, ring, and primary (the sidebar stays dark in light mode)
--radiusBase corner radius; drives --radius-sm…--radius-2xl

Dark Mode

Dark mode is implemented by toggling a .dark class on the <html> element. The Tailwind dark variant is configured once in main.css:

@custom-variant dark (&:is(.dark *));

This lets you write dark:bg-card style utilities in your markup, while the .dark block in main.css overrides every semantic token at once. There is no ThemeProvider and no React — runtime theme state is handled by a small module, src/lib/theme.js, which persists the choice to localStorage under the key apex-theme:

import { setTheme, toggleTheme, getResolvedTheme } from "./lib/theme.js";

setTheme("dark");    // "light" | "dark" | "system"
toggleTheme();       // flips between light and dark
getResolvedTheme();  // "light" or "dark" (resolves "system")

The theme toggle in the header (a sun/moon button) simply calls toggleTheme(). The "system" value follows the operating-system preference via matchMedia("(prefers-color-scheme: dark)") and reacts to OS changes in real time. When the theme changes, theme.js dispatches an apex:themechange event so charts can re-read the OKLCh chart tokens and repaint.

Preventing the Theme Flash (FOUC)

Module scripts load after the page paints, so applying the theme only from theme.js would cause a flash of the wrong theme on first load. To avoid this, every page includes a tiny inline script in the <head> that runs before the body renders. It reads the saved preference and applies .dark + color-scheme synchronously:

<script>
  (function () {
    try {
      var t = localStorage.getItem("apex-theme") || "system";
      var dark = t === "dark" || (t === "system" &&
        matchMedia("(prefers-color-scheme: dark)").matches);
      var el = document.documentElement;
      el.classList.toggle("dark", dark);
      el.style.colorScheme = dark ? "dark" : "light";
              var _ce=document.documentElement;var _ca=localStorage.getItem("apex-accent");if(_ca)_ce.dataset.accent=_ca;var _cr=localStorage.getItem("apex-radius");if(_cr)_ce.style.setProperty("--radius",_cr);var _cd=localStorage.getItem("apex-dir");if(_cd)_ce.dir=_cd;
        } catch (e) {}
  })();
</script>

Copy this block into the <head> of every new page. The dashboard pages extend it slightly to also restore the collapsed-sidebar state from apex-sidebar-collapsed. The runtime module, initTheme(), then takes over once the page has hydrated to handle toggles and live OS changes.

RTL Support

The layout is built with CSS logical properties, so it works in right-to-left languages (Arabic, Hebrew, Persian, Urdu) when you set dir="rtl" on the <html> element. The sidebar slides in from the correct edge, borders and spacing flip automatically, and the content offset follows. The implementation relies on:

  • CSS logical properties — instead of physical ml-*/mr-* and pl-*/pr-*, the markup uses ms-*/me-*, ps-*/pe-*, text-start/text-end, and border-s/border-e. These flip with the document direction.
  • CSS that keys off [dir="rtl"] — the sidebar uses inset-inline-start and a [dir="rtl"] .apex-sidebar-aside rule so the off-canvas drawer translates from the right edge, and the content margin uses margin-inline-start.
  • The dir attribute on <html> — browsers natively reverse text flow, scroll direction, and table column order when this is set.
<!-- Classes that work in both LTR and RTL -->
<div class="ms-4 me-2 ps-3 pe-3 text-start border-s">
  Content flows correctly in both directions
</div>

<!-- Enable RTL for the whole page -->
<html lang="ar" dir="rtl">
