Components

The framework-free Apex Dashboard ships two kinds of reusable building blocks: CSS component classes (prefixed apex-) for buttons, inputs, cards and badges, and web components (custom elements like <apex-sidebar> and <apex-data-table>) for the larger, interactive pieces. There is no React, no JSX, and no build-time component model â€” everything is plain HTML you can copy and paste.

How the Components Work

All custom elements are light-DOM custom elements: they render their markup directly into the page (no Shadow DOM), so every Tailwind utility class and CSS custom property applies to them exactly as it would to any other element. Layout components such as <apex-revenue-chart> use display: contents so their inner col-span-* wrapper participates in the page grid directly.

Custom elements are registered in src/main.js (dashboard pages) and src/docs.js (docs pages). Drop one module into the page and the elements upgrade automatically: 

<!-- at the end of <body> -->
<script type="module" src="/src/main.js"></script>

Icons

Icons are Lucide (the vanilla lucide package, not lucide-react). Write an <i data-lucide="name"> placeholder, then renderIcons() swaps it for an inline SVG. Only a curated set of icons is bundled (see src/lib/icons.js) so the page stays lean â€” use a name from that list, or add an import + map entry to enable more. 

<i data-lucide="layout-dashboard" class="h-4 w-4"></i>
<i data-lucide="trending-up" class="h-3.5 w-3.5 text-success"></i>

Note: data-lucide names are kebab-case (layout-dashboard, trending-up, more-horizontal). After injecting markup dynamically, call renderIcons() again â€” it is idempotent and skips already-rendered icons.

Data Display

Badge

Badges are small status pills. There is no single class â€” they are a short utility recipe with a color pair drawn from the semantic tokens (success, primary, warning, destructive). The <apex-data-table> uses the same recipe for its badge column type. 

<span class="inline-flex items-center rounded-md px-2 py-0.5
  text-[11px] font-medium bg-success/15 text-success">completed</span>
<span class="... bg-primary/15 text-primary">processing</span>
<span class="... bg-warning/15 text-warning">pending</span>
<span class="... bg-destructive/15 text-destructive">cancelled</span>

Tabs

A tab list is a flex row with a muted background; each tab uses .apex-tab and the active one adds .apex-tab-active. Interactivity is wired by initTabs() in src/lib/tabs.js. 

<div class="inline-flex gap-1 rounded-lg bg-muted p-1">
  <button class="apex-tab apex-tab-active">Overview</button>
  <button class="apex-tab">Activity</button>
</div>

Layout Web Components

These elements build the dashboard chrome and the home page. They read mock data from src/lib/data.js and have no attributes â€” drop them in and they render. They are display: contents (except where noted) so the inner grid wrappers slot into the page layout.

<apex-sidebar> & <apex-header>

<apex-sidebar> is the collapsible left navigation (it also reads the apex-sidebar-collapsed localStorage flag set by the no-flash head script). <apex-header> is the top bar with search, theme toggle and notifications. Every dashboard page wires them together with the .apex-content wrapper that offsets the main area by the sidebar width. 

<div class="flex min-h-screen bg-background">
  <apex-sidebar></apex-sidebar>
  <div class="apex-content flex min-h-screen flex-1 flex-col">
    <apex-header></apex-header>
    <main id="main-content" class="flex-1 p-4 sm:p-6">
      <!-- page content -->
    </main>
  </div>
</div>

<apex-stats-cards>

Four metric cards (revenue, users, orders, views), each with a trend indicator and an ApexCharts area sparkline pinned to the bottom edge. Renders the statsData array. 

<apex-stats-cards></apex-stats-cards>

The main overview chart with Revenue / Orders / Profit tabs. Revenue and Profit render as gradient area charts; Orders renders as a bar chart. Spans 8 of 12 grid columns on wide screens.

Data Components

<apex-chart>

A generic, config-driven chart powered by ApexCharts. Each instance carries its own data in a child <script type="application/json">, so charts share no state and stay copy-pasteable. The full attribute reference and more live examples are on the Charts page. 

<apex-chart data-type="area" data-colors="chart-1" data-height="300" data-y-format="compact">
  <script type="application/json">
    { "series": [{ "name": "Revenue", "data": [12,18,15,22,28,30] }],
      "categories": ["Jan","Feb","Mar","Apr","May","Jun"] }
  </script>
</apex-chart>

<apex-data-table>

A fully interactive, config-driven table: sorting, global search, filter tabs, pagination, row selection with bulk delete, row-click navigation, dropdown or inline row actions, sparkline cells and CSV export. Behaviour is controlled with data-* attributes; the data and columns live in one inline JSON child.

Attribute Meaning
data-searchSearch input placeholder
data-selectable"true" adds row checkboxes + bulk delete
data-row-hrefRow-click target, e.g. order-detail.html (supports {id} tokens)
data-exportAdds an Export button; value is the CSV filename
data-page-sizeInitial rows per page (default 10)

Column type values: text, mono, entity, badge, currency, number, date, sparkline and actions. 

<apex-data-table data-selectable="true" data-row-href="/order-detail.html"
                 data-export="orders" data-search="Search orders..." data-page-size="10">
  <script type="application/json">
  {
    "idKey": "id",
    "filter": { "key": "status", "tabs": [
      { "label": "All", "value": "all" },
      { "label": "Completed", "value": "completed" }
    ]},
    "columns": [
      { "key": "id", "label": "Order", "type": "mono", "sortable": true, "search": true },
      { "key": "status", "label": "Status", "type": "badge",
        "map": { "completed": "success", "pending": "warning" } },
      { "key": "amount", "label": "Amount", "type": "currency", "sortable": true, "align": "end" },
      { "type": "actions", "style": "dropdown", "align": "end", "actions": [
        { "label": "View", "icon": "eye", "href": "order-detail.html" },
        { "label": "Delete", "icon": "trash-2", "action": "delete", "variant": "destructive" }
      ]}
    ],
    "rows": [
      { "id": "ORD-7891", "status": "completed", "amount": 299 },
      { "id": "ORD-7888", "status": "pending", "amount": 79 }
    ]
  }
  </script>
</apex-data-table>

Tip: set "search": true on the columns that the global search box should match, and "sortable": true on the columns the header should sort by. See orders.html for a complete real-world configuration.
